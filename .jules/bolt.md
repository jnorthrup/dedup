## 2026-10-28 - Zero-Copy Queue Transfers and Direct Open Sycalls
**Learning:** Moving file entries between worker queues (`raw_queue` -> `queue`) previously allocated a new `FileEntry` struct, `strdup`'d the path, and freed the old struct, causing 2 heap allocations and 2 frees per surviving file. Reusing `FileEntry` objects via `file_entry_queue_push` avoids dynamic memory churn on the critical path. Additionally, opening files with `O_NONBLOCK` and immediately calling `fcntl(F_GETFL)` and `fcntl(F_SETFL)` to clear `O_NONBLOCK` added 2 redundant kernel syscalls per signature calculation.
**Action:** Always check queue pipeline transfers for object ownership reuse instead of copy-and-delete patterns, and ensure `open()` call flags don't require subsequent `fcntl()` roundtrips for regular files.
