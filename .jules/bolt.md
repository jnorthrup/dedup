## 2026-10-19 - C Hash Set Memory Layout & Struct Padding Optimization
**Learning:** In C hash tables using open addressing/linear probing, using a struct for slots with non-aligned scalar fields (e.g., `uint64_t key` + `uint8_t state`) causes implicit compiler alignment padding (7 bytes padding per 9 bytes payload), wasting 43.7% of memory and reducing L1 cache line slot density by 50%. Replacing state flags with a sentinel value (e.g., `0` for empty slots) and tracking edge-case keys (like `0`) via a struct field cuts memory per slot from 16 to 8 bytes and doubles cache density (8 slots vs 4 slots per 64-byte L1 cache line).
**Action:** When designing fast C hash sets/tables, always check `sizeof(Slot)` for alignment padding and consider flat primitive arrays with sentinel values for empty slots.
